## 🎯 Migração do Storage para OCI Object Storage via Terraform com PAR e CI/CD Automatizado

### 📋 Resumo da Intervenção
- **Contexto**: O projeto PS operava com armazenamento local de arquivos em disco (`STORAGE_PROVIDER=local` em `/opt/ps/data/uploads`). Esta entrega implementa a migração do armazenamento de arquivos e relatórios para o bucket privado `ps-files` na Oracle Cloud Infrastructure com `STORAGE_PROVIDER=oci`.
- **Estratégia 100% como Código**: Provisionamento de Solicitação Pré-Autenticada (PAR) com expiração estendida (`2035-12-31T23:59:59Z`), permissão `AnyObjectReadWrite` e listagem de objetos via Terraform (`oci_objectstorage_preauthrequest.files_par`).
- **Automação Zero-Intervention no CI/CD**: O pipeline de deploy do Backend (`.github/workflows/backend.yml`) resolve automaticamente o endpoint autenticado a partir do arquivo de estado remoto `terraform.tfstate` armazenado no bucket de estado da OCI, eliminando intervenções manuais ou criação prévia de secrets.

### 🛠️ Modificações por Camada
- **Infraestrutura como Código (Terraform)**:
  - `terraform/object_storage.tf`: Adicionado recurso `oci_objectstorage_preauthrequest.files_par` vinculado ao bucket `oci_objectstorage_bucket.files.name`.
  - `terraform/outputs.tf`: Adicionado output sensível `object_storage_endpoint` apontando para a URL PAR completa.
  - `.github/workflows/terraform.yml`: Adicionado passo `Export Outputs to Step Summary` para exibir o endpoint autenticado no resumo da execução.
- **Pipelines e Automação de Deploy (CI/CD)**:
  - `.github/workflows/backend.yml`:
    - Adicionado passo `Resolve Terraform outputs from OCI state` no job `deploy-oci` para baixar dinamicamente `terraform.tfstate` via OCI CLI e extrair `object_storage_endpoint`.
    - Adicionadas variáveis no passo `Apply updates and restart services on OCI` (`STORAGE_PROVIDER`, `OCI_STORAGE_BUCKET`, `OCI_STORAGE_NAMESPACE`, `OCI_STORAGE_REGION`, `OCI_STORAGE_ENDPOINT`).
    - Configurado loop de injeção defensivo no `/etc/ps/backend.env` para atualizar as configurações de storage no servidor.
- **Scripts de Ambiente & Sincronização**:
  - `scripts/sync-env.sh`: Extração de `object_storage_endpoint` dos outputs do Terraform, alteração do padrão para `STORAGE_PROVIDER=oci` e injeção de `OCI_STORAGE_ENDPOINT`.
- **Backend / Infraestrutura**:
  - `backend/internal/infrastructure/storage/oci/provider.go`: Suporte a endpoints PAR contendo `/p/` para composição transparente de URLs (`PUT`, `GET`, `DELETE`) e dispensando obrigatoriedade redundante de namespace/bucket quando embutidos no PAR.
  - `backend/internal/infrastructure/storage/oci/provider_test.go`: Criação de suíte de testes unitários cobrindo URLs padrão, endpoints PAR com e sem barra final, operações HTTP reais com `httptest.Server` e validação contra path traversal.
- **Configurações & Documentação Canônica**:
  - `.env.example` e `deploy/backend.env.example`: Adicionadas variáveis de configuração para OCI Object Storage.
  - `docs/operations/environment-and-config.md`: Matriz de variáveis e documentação da arquitetura PAR e resolução em pipeline.
  - `docs/architecture/storage-and-media.md`: Atualização sobre OCI Object Storage e Pre-Authenticated Requests.
  - `docs/log.md`: Atualização do índice cronológico com nova entrada e timestamp atualizado.
